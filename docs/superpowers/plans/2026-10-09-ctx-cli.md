# ContextHub CLI implementation

Goal: provide Linux/remote-terminal conversation workflows analogous to Git + GitHub, with persistent per-origin login and explicit local commits.

Authorized scope follows the user's request for the companion tool and Linux preference. Keep public read/private owner access and all download/write login requirements.

## Architecture

- `workspace.py`: managed library/conversation JSON, immutable contextpack objects and local commit records, index/HEAD/remote state, file locks and rollback journal. No project scan or Git hooks.
- `hub_client.py`: stdlib HTTPS client, literal loopback HTTP for local development, no redirect, origin-scoped 600/700 credentials, bounded transport and sanitized output.
- `ctx.py`: `auth`, `init`, `add`, `diff`, `status`, `commit`, `log`, `push`, `pull`, `clone`, `fork`, `remote`, `export`, and Codex bridges.
- `POST /api/packages/:id/push`: authenticated owner-only canonical snapshot verification, same audit construction as web revisions, existing CAS/idempotency. Initial upload accepts optional commit message.
- `distribution.py`: deterministic zipapp with explicit source-module allowlist; public download/checksum/guide, no database or credentials in distribution.

## Semantics

- Initial push defaults private and preserves every local commit in order; successful remote responses advance one checkpoint at a time.
- Clone starts at a pinned snapshot. Pull requires clean worktree and no unpushed commits; no force, auto-merge or reset.
- Canonical local commits preserve existing provenance. Server recomputes audit records and compares all semantic fields, preventing raw-pack audit bypass while allowing ZIP compression differences across machines. Accepted original bytes and hashes are preserved.
- Add uses explicit imports; add-dot stages only managed JSON. Conflict replacements require `--replace`.
- Login secrets live outside workspaces and never enter portable artifacts. Public libraries require login for download.

## Validation and delivery

Use synthetic fixtures and temporary Hub instances for local staging semantics, multi-commit/two-machine sync, stale-base conflict, retry, ACL, credentials, path safety and crash recovery. Test zipapp outside the source checkout and confirm browser guide on desktop/mobile. Run full regressions, review cross-module behavior, back up production before restarting on verified source, install local `ctx`, and record exact evidence in the verification document.
