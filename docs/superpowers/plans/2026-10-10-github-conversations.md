# Vibe coding 对话仓库实施计划

**目标：** 以对话为版本管理主对象，采用 GitHub 风格仓库体验，再建立对话版本与代码提交的关联及协调恢复。

**依据：** [修订设计](../specs/2026-10-10-github-conversations.md)。此前的 `.context/` attach/read/ZIP 计划取消；已有 Git export/import 保留。

**状态：** 首版实现已完成，完整验收结果见 [验证记录](../../verification/2026-10-10-vibe-coding.md)。已归并到用户指定的唯一开发目录 `/ssd1/code/yqq/Git_for_ai`，该目录的公网服务已更新。后续不再另建开发工作树。Windows 原生验收仍待执行。

## 1. 对话仓库页面

- 改造 `static/index.html`、`repository.css`、`repository.js`、`app.js`：顶部导航、owner/name、仓库列表、版本选择、对话主视图及 About 信息。
- 复用现有版本比较、Fork、贡献请求、草稿与权限流程；仅对已存在的能力提供入口。
- 用浏览器验证桌面及移动端阅读、导入下载、草稿恢复与贡献回归，并保存截图。

## 2. 固定版本的代码关联

- 先定义可携带的关联 schema 与兼容版本：仓库标识、完整提交 ID、可选分支提示、验证状态；本机位置独立保存。
- 将关联纳入不可变对话版本或检查点记录；明确内容哈希、历史迁移、导入导出、Fork 和合并规则，不采用会改变旧版本含义的可变旁注。
- 扩展包格式、Workspace、Hub 存储及 API，再提供 ctx 绑定/查看操作和网页关联代码面板。
- 验证旧包兼容、JSON 校验、权限、去凭据与本机路径隔离，以及推送/克隆/Fork 后关联保留。

## 3. 联合检查点与恢复

- 本机连接器收集准确对话版本和代码提交，区分干净、含未提交修改、不可验证等状态；首版只将已提交的干净代码状态标为可恢复。
- 定义恢复计划和操作日志；优先使用新会话与独立代码 Git 浅仓库，保留当前会话和工作区。
- 分别检查对话取得、代码提交取得、会话适配和权限；记录逐项结果，配对准备失败可重试，原生导入不确定时保留结果并拒绝自动重试，禁止误报同步成功。
- 加入分支移动、缺失提交、脏工作区、恢复中断、部分完成和重试测试。原生会话恢复沿用各来源已验证的能力边界。

## 4. 验收与交付

- 使用合成 vibe coding 项目验证“对话迭代 → 代码提交 → 联合检查点 → 分支探索 → 差异查看 → 成对恢复”。
- 运行相关 Python、CLI、浏览器与 Windows 检查，逐项记录已验证能力。
- 更新 README 与 CLI 文档，明确 GitHub 代码权限、ContextHub 对话权限以及同步边界；未完成的能力不写成已支持。
