# ContextHub 日常使用能力完善

用户要求先同步远端，再解决单分支、Codex 时间线、网页草稿、仓库生命周期和 Windows 预览限制。起点为远端 `ceda7f5`，本地已 fast-forward，无冲突。开发使用独立工作区，不直接修改运行中的服务。

用户已选择 Git 范围：ctx 分支和合并，以及普通 Git 仓库双向导入/导出。本轮不增加 Hub Git HTTPS 服务。标准 Git 的网络传输由 Git 自身提供。

## 实施与验收

1. 工作区：兼容旧状态；命名分支、切换、提交 DAG、三方合并和拉取合并。冲突不覆盖任何一边，脏工作区不得切换。普通 Git 仓库可保存受管内容和历史，导入不执行 hooks、filters 或项目文件。
2. Codex：使用隔离 Codex 存储和合成正文验证新会话中可见的用户/助手时间线；明确支持的客户端版本。保留 context 模式，不迁移凭据、工具权限和项目状态，不调用模型或读取真实会话。
3. 草稿：按拥有者和对话库存到服务器，800ms 去抖，刷新恢复；草稿不公开且不产生发布版本。递增 revision 防止多标签覆盖，失败保留页面内容，可下载备份。发布与丢弃只清理匹配 revision 的草稿。
4. 可见性：拥有者显式转换，服务端校验版本与来源约束，重新检查搜索、下载、贡献和来源信息权限。
5. 删除：维持撤销访问，增加明确确认的永久清理，保护其他库/Fork 所需的共享文件；清理可重试。不主动清理生产中既有删除库或运维备份。
6. Windows：同步已有 Windows 11 原生验收修复，核实可用 CI 权限并运行原生矩阵。正式支持范围以实际证据界定，不能仅删除预览文字。

每个子系统添加行为测试，完整 Python 回归和浏览器验证后，进行代码复审；上线前停止服务备份数据。公网验证只做读取及匿名操作拒绝，不在生产创建合成账号或对话。
