# ContextHub：面向 vibe coding 的对话版本平台

## 用户确认的定位（2026-10-10 修订）

ContextHub 把 AI 对话像代码一样管理。仓库、提交、分支、Diff、Fork 和合并围绕对话展开；在 vibe coding 场景中，对话的演化需要与关联代码的演化对应起来。界面及操作习惯接近 GitHub，兼容已有代码仓库。

此前“把对话文件附带到代码仓库，由普通 Git 一起携带”的设计已被本次澄清取代。Git 可以保存显式加入版本管理的任何文件，但不会自动捕获 Codex、Claude 等工具的会话，也不提供对话语义、会话恢复或代码与对话的协调回退。

## 产品对象

- **对话仓库**：独立保存对话、来源、版本与协作关系；可以不关联代码仓库，继续支持一般 AI 对话管理。
- **对话版本**：不可变的对话快照及父版本，支持按消息查看差异、分支实验和贡献合并。
- **代码关联**：指向已有 Git/GitHub 项目与固定提交。分支名仅用于展示，不能代替不可变提交标识。机器路径只在本机配置中保存，不随分享包传播；远端地址去除凭据。
- **联合检查点**：首版记录对话版本与一个代码仓库的准确提交。二者保留各自历史，通过检查点建立可验证的对应关系。

检查点必须区分“用户声明的关联”与“本机已验证的状态”。代码工作区存在已跟踪或未跟踪修改时，HEAD 不能代表当前工作区，不能将检查点标为可完整恢复。首版联合检查点要求代码已明确提交且相关工作区干净；临时代码快照能力另行实现。

## 典型工作流与同步语义

1. 开发者使用 Codex / Claude 等工具进行需求讨论和编码。
2. 连接器捕获受支持的对话，ctx 保存对话版本；没有连接器的来源仍支持显式导入。
3. 在可复现的节点，将对话版本与本机验证过的代码提交关联，形成检查点。
4. 在 Hub 查看检查点，同时阅读对话差异与关联的代码差异。外部代码不可访问时明确提示，对话仍按自己的权限管理。
5. Fork 对话可创建新的探索路线；代码 Fork 是独立操作，需要记录新的代码仓库及共同起点，不声称对话 Fork 已复制代码。
6. 恢复时分别提供“仅恢复对话”和“恢复对话及关联代码”。联合恢复先验证两个版本均可取得、工作区状态和恢复目标，再执行并记录结果。

对话版本恢复、Agent 原生会话恢复、代码检出是三个不同结果。原生格式不支持的工具状态、附件或运行环境不会因代码回退而恢复。跨工具与代码仓库不能宣称天然原子操作；联合恢复需要操作日志、失败补偿及可重试状态，未完成前不能显示同步成功。首版恢复到新的会话及独立代码 Git 浅仓库，保留当前工作。代码与对话在临时目录准备后原子发布；原生导入在发布后执行，回执区分完成与不确定状态，不确定时拒绝自动重试。

代码与对话的合并也分别检查：对话合并成功不等于代码合并成功。合并后产生新的对话版本，只有验证关联的合并后代码状态后才生成新联合检查点。

## GitHub 风格界面

采用紧凑顶部导航、owner / repository 标题、仓库列表、分支或版本选择和右侧仓库信息。仓库主视图是对话列表与消息阅读；提供对话、版本历史、差异、贡献请求、关联代码与设置入口。

关联代码区域显示仓库、固定提交、检查点状态以及查看代码差异的入口。尚未实现的分支、检查点或同步能力不伪装成可用按钮。现有 Hub 与本地 ctx 的能力差异需明确标注。

下载菜单优先提供对话迁移包与 ctx 使用方式。将 JSON 放入 Git 只是可选互通方式，不作为主要产品模型；本轮撤销 attach/read 与 `.context/` 附加 ZIP 的开发计划。

## 权限与现状

公开对话库可匿名阅读；所有下载与写操作须登录；私有对话库仅所有者可见。关联代码遵循代码托管方的独立权限，对话公开不会使私有代码公开。公共检查点不能夹带私有代码正文、凭据或本机路径。

当前开发版本 0.8.0 已实现本地对话分支、三方合并、Git 格式互通、Hub 版本比较及 Fork/贡献流程，以及代码关联、联合检查点和独立目录恢复。网页使用 GitHub 风格对话仓库布局，恢复通过本机 ctx 执行。GitHub 仓库权限由代码托管方管理；没有新增自动 GitHub OAuth 同步或平台内代码托管。本地完成不代表公网部署已更新，详见本轮验收记录。

## 验收场景

- 纯对话库仍可导入、提交、比较、Fork、下载，不依赖 GitHub 项目。
- 同一项目两条对话探索路线可关联不同代码提交，不互相覆盖。
- 修改或移动代码分支后，历史检查点仍指向原固定提交。
- 脏工作区、缺失提交、代码权限不足或恢复中断不能报告联合恢复成功；当前工作保留，可恢复或重试。
- 分享、克隆、Fork 保留可携带的关联信息，但不会自动复制代码、授权代码访问或暴露本机配置。
- 浏览器验证 GitHub 风格对话仓库布局、移动端、历史版本、草稿与贡献流程；检查点功能完成后增加端到端验证。

## 首版实现与边界

`ctx checkpoint --code PATH -m MSG` 捕获匹配版本；`ctx restore REF --code PATH --to NEWDIR` 成对恢复，`--codex` 可选原生导入，`--resume` 核验已完成的同一恢复。支持 SHA-1/SHA-256 Git 与 linked worktree。对话库和代码分别维护历史，恢复后的代码为独立浅仓库。

只处理普通文件，不调用源 Git 配置、钩子或过滤器；要求捕获时工作文件与对象字节一致。子模块、符号链接、LFS 及受换行/过滤器转换的检出暂不支持。对象内容重新计算哈希，拒绝损坏或不匹配的 commit/tree/blob，恢复只读取验证后的副本。代码差异目前通过关联的 GitHub 提交页面查看，尚无平台内双栏代码 Diff。
