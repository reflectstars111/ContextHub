## 1. 产品优先级

用户的核心需求是方便地导出、上传、下载和导入对话。首版必须围绕下面的真实使用路径设计：

```text
Alice 的 Codex
    ↓ 多选会话，预览和脱敏
ContextHub 迁移包
    ↓ 上传指定对话库，发布固定版本
ContextHub 网页：阅读、搜索、下载
    ↓ Bob 下载选定对话或整个包
Bob 的本地连接器
    ↓ 转换、创建新线程、验证导入结果
Bob 的 Codex：使用自己的账号和项目继续讨论
```

ContextHub 管理和传递已有内容。继续调用模型发生在接收者自己的 Codex 中，不引入 ContextHub 托管模型服务。

## 2. 已核实的事实与尚未验证的部分

检查了本机 `codex --version`、`--help`、`resume --help`、`fork --help`、`app-server --help`，并对比了该二进制生成的普通与实验协议类型。没有读取凭证或私人对话正文，没有启动模型调用，没有修改现有 Codex 会话。

| 能力 | 本机证据 | 实现结论 |
|---|---|---|
| 通用 CLI 导入/导出 | 命令列表没有通用 `import` / `export` | ContextHub 需要提供自己的适配器 |
| `codex resume` / `codex fork` | 使用已有 session ID/名称等选择会话 | 不是任意下载文件的通用导入入口 |
| 会话列表 | `thread/list`，游标分页与来源、归档筛选 | 可作为批量选择会话的接口基础 |
| 会话读取 | `thread/read`、`thread/turns/list`、`thread/items/list` | 需要按存储模式和接口能力读取 |
| 新线程 | `thread/start` | 接收者建立属于自己的新线程 |
| 历史上下文加入 | `thread/inject_items` 存在于普通协议导出 | 可作为结构化导入候选，仍须实测 |
| 原生文件路径恢复 | `resume.path` / `fork.path` 仅在实验类型中存在，标记 UNSTABLE | 不能作为不受版本限制的产品承诺 |
| `resume.history` | 实验类型注明 Cloud 专用、DO NOT USE | 不作为公开连接器的稳定依赖 |

官方文档也说明了会话读取、创建、恢复和注入历史的接口；`thread/inject_items` 会将条目加入模型可见历史并持久化。[Codex App Server 文档](https://learn.chatgpt.com/docs/app-server#inject-items-into-a-thread)。CLI 恢复命令的用途见[官方命令说明](https://learn.chatgpt.com/docs/developer-commands?surface=cli#codex-resume)。

**这证明存在可集成的技术基础，尚不证明下载文件已经能够在任意版本的 Codex App/CLI 中无损恢复。** 接口生成类型也不能替代运行时、持久化与界面验证。

如果接口不支持结构化导入，兜底提供上下文文件和在 Codex 中打开的引导，明确标为“作为参考资料继续”，不算主链路已通过。

## 4. 连接器的使用体验

安装一次本地 ContextHub 连接器，随后使用本地选择界面或开发者 CLI。网页仍支持直接上传已生成的迁移包；不要求用户找到内部数据库或手动复制隐藏目录。

导出端：

1. 检测 Codex 版本和连接能力，展示可读取的会话。
2. 按标题、项目、时间筛选，多选；“含归档会话”与“含子会话”分别选择。
3. 可选择完整对话或指定已完成消息范围；展示每段消息数量与附件/工具记录状态。
4. 本地预览，检查凭证和敏感路径，用户决定删减或脱敏。
5. 生成迁移包，保存到本地；用户选择上传库及公开范围后上传。

接收端：

1. 下载单篇对话或整个库的固定版本迁移包。
2. 连接器展示来源、对话数量、兼容性和遗漏说明。
3. 用户选择目标项目及要导入的对话。
4. 每篇创建新的本地线程，不覆盖已有线程；生成导入回执。
5. 提供在已验证 Codex 界面打开的入口；用户自行发送新消息继续。

本地连接器如提供 loopback UI/API，必须具有每次会话的认证能力、来源校验和明确的本地选择；公共网页不能无认证读取本地会话。导出和导入本身不自动启动新的模型生成。

## 5. 批量导出的技术要求

- `thread/list` 必须遍历全部 `nextCursor`；归档与未归档按用户选择分别读取。
- 省略 `sourceKinds` 默认只列出交互来源；若用户选择包含非交互或子会话，显式传入相应来源类型。
- 按 `historyMode` 和能力探测选择读取方式；不要假定所有会话都存在可独立搬运的完整 JSONL。
- `thread/turns/list` 默认 `itemsView=summary`，不能据此声称导出完整正文。需要 `full` 或逐项分页读取，并验证无剩余游标。
- 对活动会话先选择稳定的已完成范围，记录边界；读取期间历史变化时重试或标为未完成快照。
- 保留可用的顺序、角色、正文和来源；无法读取的项写入报告，不默默删除后显示“完整导出”。

本机还只读检查了存储表结构，发现会话索引和分页历史数据库并存。这是特定安装状态，不作为外部稳定格式；禁止直接写入接收者的 SQLite 作为常规导入路径。

## 6. 导入 Codex 的适配路径

待验证的优先路径：初始化本地 App Server → `thread/start` 创建新线程 → 转换并 `thread/inject_items` → 读取核对与重启恢复 → 将新线程交给用户。

读取返回的 `ThreadItem`（如 `userMessage`、`agentMessage`、`commandExecution`）与注入接收的 raw Responses API items 不是同一个 schema。必须显式实现转换，不能将读取结果直接回灌。

首版默认映射可公开的用户与助手文本。原来的系统/开发者指令只在用户选定后作为带标签的参考文本保存，不提升为新线程的有效高权限指令；目标环境沿用接收者自己的权限和配置。

历史工具调用与输出可作为已发生事件的阅读记录，不能重新触发执行。缺失本地文件、工具、MCP、网络资源或附件时明确报告。绝对工作目录由接收者重新选择，不照搬来源机器路径。

导入日志保留本地新旧 ID 映射、ContextHub 版本与摘要；导入过程失败时标记中间线程，不把部分完成当作成功。只有核对数量与内容、重新打开且继续使用通过，才允许显示相应兼容标记。

超长历史需要提前检查目标限制，支持用户明确选择范围或分段参考；不静默截断。导入不保证模型每次都把完整历史放进上下文窗口，也不保证回答逐字一致。

## 7. 迁移包

拟定使用 `.contextpack` 扩展名，内部是标准 ZIP：

```text
manifest.json                   # 格式版本、条目清单、大小、SHA-256
library.json                    # 库描述与公开来源
conversations/*.json            # 规范化对话，迁移主数据
readable/*.md                   # 从同一主数据生成的阅读版
compatibility.json              # 来源版本、内容覆盖、遗漏、目标模式
```

不直接打包用户目录、认证、配置、数据库或原始日志。若将来提供个人原生备份，应与公开迁移包使用独立流程和明显不同的标记。

SHA-256 校验传输与版本一致性，不代表内容可信或来源已认证。文件路径、数量、解压后总大小及单文件大小必须校验；拒绝越界路径和符号链接。阅读版由规范化主数据生成，脱敏后不能残留未脱敏的另一份表示。

初始建议每篇规范化对话上限 5 MiB、每包解压总量 100 MiB、最多 200 篇，可分批传输并显示逐篇结果。超限在本地打包前提示；这些是待样例验证的默认限制。

## 8. 首个验收里程碑

先在两个隔离的测试用户环境 A/B 中证明可往返迁移，再扩大平台功能：

1. A 准备多轮中文、代码块、长文本以及附带工具记录的合成会话，不读取或上传用户真实私人数据作公开测试。
2. 从 A 多选导出，逐条核对标准包内容和遗漏报告。
3. 上传到本地 ContextHub 试验服务，B 下载固定版本并核对摘要。
4. B 导入得到新的本地 ID，A 的原会话与 B 的既有会话不变。
5. B 的目标 Codex CLI/界面能打开导入内容；重启后仍可见。
6. 用户用自己的 Codex 发起一个新问题，确认导入上下文可供使用。该步骤是真实续聊验证，需可用模型访问；仅 schema 与存储检查不算通过。
7. 将 B 的后续对话再次导出，来源仍可追溯至 A 的公开版本。

第一轮至少分别报告：读取、规范化、往返内容、存储恢复、CLI 可见性、桌面 App 可见性、实际续聊。未测试的界面标为未测试，不能用 CLI 通过推断所有客户端通过。
