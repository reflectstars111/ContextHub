日期：2026-10-09（Asia/Shanghai）。实现分支：`feature/contributions`。本阶段在导入导出、版本与 Fork 之上，完成公开改进回流：固定版本提案、双方讨论、候选审阅和合并发布。

## 自动化结果

`python3 -m unittest discover -s tests -v`：**124 项通过**。包括原有 77 项，以及新增 25 项三方合并、17 项贡献存储、5 项真实 HTTP 测试。

- 稳定 ID 匹配对话和消息，合并独立字段修改；同字段不同修改、删除/编辑、同 ID 不同新增与矛盾顺序阻止发布。
- 目标库来源保持不变；审计前缀、同分支重复记录和删除对话的历史记录保留。超出包格式上限的合并变成冲突，不生成候选。
- 冲突详情最多 100 条、每个字段最多 2,000 字符，完整冲突数量仍准确并标记截断。
- 提案固定源版本。源库后续新版本不改变候选；显式更新提案版本、关闭或重新打开会清除旧检查。
- 上游新版本使检查过期。客户端必须提交准确 `check_id` 与 `candidate_oid`；旧检查、冲突或空变化不能合并。
- 检查不发布版本。合并发布与审阅候选相同的 ZIP 字节和 Git OID，Git 父提交为目标旧 head 和固定源版本。
- 两个 Store 实例重试同一候选只生成一个版本；不同候选竞争时只有一个成功。Git 失败或数据库失败不会推进业务 head、历史或公开 ref。
- 评论、状态、源版本更新、检查与合并各自限制角色；CSRF、匿名写入、跨账号写入被拒绝。评论上限 200 条。
- 每次读取和修改重新验证公开源、公开目标与 Fork 点依赖。依赖删除或转为不可访问后，列表隐藏，详情、候选与写操作拒绝。
- ZIP 压缩方式或表示不同但完整规范内容相同，不会产生空提案或空候选。

## 真实浏览器验收

```bash
python3 scripts/verify_web.py
python3 scripts/verify_versions_web.py
python3 scripts/verify_contributions_web.py
node --check contexthub/static/app.js
node --check contexthub/static/versions.js
node --check contexthub/static/contributions.js
```

本环境以 `PYTHONPATH=/tmp/contexthub-browser-libs` 加载可选 Playwright。三个浏览器脚本和语法检查通过，JavaScript 异常为 0。旧脚本回归上传/下载、公开/私有权限、连接器合成导入导出，以及版本、Fork、编辑、整包更新与草稿保护。

新脚本使用临时 Hub、两个实际注册账号和 Chromium：

1. Alice 上传公开库，Bob 公开 Fork、编辑并发布 v2，从网页创建固定版本提案；刷新提案链接仍可阅读。
2. 延迟提案读取后开始编辑，旧响应不会替换新草稿。
3. 延迟评论提交时继续输入，新评论草稿保留；站内返回与再进入仍可继续编辑。HTML 示例只作为文本显示。
4. Alice 检查候选，先展开本次变化才可合并；下载完整候选后，检查上游尚未改变。
5. Bob 再次发布源版本，但已提交提案仍使用 v2；Alice 合并后，上游下载字节和 Git OID 与候选完全一致，可跳转到合并后的固定版本。
6. 第二个提案检查后，Alice 改动上游同一回答；旧合并收到 409 并禁用，未提交评论保留。重新检查显示共同起点、上游内容和提案内容，冲突不能合并。
7. Bob 显式更新源版本，关闭并重新打开；旧候选清除，重新检查使用新的明确版本。
8. 匿名用户在 390px 手机宽度可读提案与候选，无评论/检查写入口，无横向溢出。
9. 提交后关闭并重新打开新提案表单，旧请求成功不会关闭新草稿或跳转，旧请求失败不会将错误写入新表单。

桌面审阅、三列冲突及手机截图已实际检查。被忽略的 `.artifacts/` 包含 `contribution-review.png`、`contribution-conflicts.png`、`contribution-mobile.png` 和 `contributions-web-verification.json`。

## 审查与修复

实现过程中用真实修订回归发现并修复审计重复被去重的问题：同一分支里完全相同的历史记录可能代表不同编辑，必须保留次数和顺序。

独立交叉审查发现仅比较 ZIP 字节会误判空改动，随后增加失败回归并改为比较完整 `library + conversations`。审查者独立复验等价 ZIP、准确候选及 Git 双父、跨 Store 重试和竞争合并，全部通过。

独立网页审查还复现了旧提案提交响应关闭新提案草稿的问题。正式浏览器脚本先观察到失败，再验证窗口身份、关闭失效和独立提交状态的修复；旧成功、旧失败都不干扰新表单。审查者另以独立浏览器夹具复验成功、失败及两个请求同时等待三种情形，全部通过；旧请求结束不会错误地解除新提交按钮的禁用状态，未发现新的阻断问题。

## 当前边界
