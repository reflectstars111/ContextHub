## 真实 Codex 的隔离迁移

执行：

```bash
python3 scripts/verify_codex_transfer.py
```

结果：成功。两份独立临时存储，源会话为 legacy 模式、目标为 paginated 模式。源端两轮共四条消息，经真实适配器导出、包写入/读取、目标新线程导入，再重启目标 app-server 并恢复；随后发往本地模拟 Responses 服务的请求中，四条导入原文逐字一致。

- 源会话未修改，已有目标会话保留，新 ID 与两者不同。
- 目标 `readOnly` / `on-request` 设置保留。
- 导出和导入本身没有开始模型 turn；验证脚本通过本地固定回复服务进行了四次测试请求。
- bwrap 隔离存储、网络与 PID，未读取真实用户会话或凭证，真实模型调用为 0。
- 公共时间线没有重建注入的历史；原生 CLI/App UI 和真实模型续聊**未验证**。

完整方法、回执字段和限制见 [Codex 探针说明](codex-probe.md)。测试进程用模拟服务验证了 Codex 发出的上下文，不代表模型理解效果，也不代表任意 Codex 版本兼容。
