WINDOWS / POWERSHELL

在 Windows 终端使用 ctx

Windows 10 / 11 原生预览版，需要 Python 3.12+。适用于 PowerShell、CMD 和 VS Code 本地终端；无需 WSL。已同步 Windows 11 本机修复；0.10.0 代码采集与恢复尚未完成原生 Windows 验收，仍保留预览标记。

先检查 py -3 --version。下载安装脚本，查看内容后运行；安装到当前用户目录，不需要管理员权限。

Invoke-WebRequest https://contexthub.reflectstars.dev/install-ctx.ps1 -OutFile .\install-ctx.ps1
Get-Content .\install-ctx.ps1
.\install-ctx.ps1
ctx --version
ctx auth login --username 你的用户名

安装器需要带 pip 或 ensurepip 的完整 Python；检查 SHA-256 后，使用本机原生启动器创建 ctx.exe，并将安装目录加入用户 PATH；新开终端即可使用。不更改 PowerShell 执行策略。若当前策略禁止脚本，或使用精简 Python，可使用下面的直接运行方式。

Invoke-WebRequest https://contexthub.reflectstars.dev/ctx.pyz -OutFile .\ctx.pyz
Invoke-WebRequest https://contexthub.reflectstars.dev/ctx.pyz.sha256 -OutFile .\ctx.pyz.sha256
$expected = (Get-Content .\ctx.pyz.sha256 -Raw).Split(' ')[0].Trim()
if ((Get-FileHash .\ctx.pyz -Algorithm SHA256).Hash -ne $expected) { throw "SHA-256 mismatch" }
py -3 .\ctx.pyz --version
py -3 .\ctx.pyz auth login --username 你的用户名

直接运行时，将后文的 ctx 替换为 py -3 C:\完整路径\ctx.pyz。安装目录为 %LOCALAPPDATA%\ContextHub\bin；登录会话由当前 Windows 用户加密保存。Windows 工作区使用本地磁盘普通目录，暂不支持网络共享、映射盘、链接或重解析点目录。

GET STARTED

Linux 安装

在 Linux 或 VS Code 远程终端中运行。先确认 python3 --version 为 3.12 或更新版本。

mkdir -p ~/.local/bin
curl -fS https://contexthub.reflectstars.dev/ctx.pyz -o ctx.pyz
curl -fS https://contexthub.reflectstars.dev/ctx.pyz.sha256 -o ctx.pyz.sha256
sha256sum -c ctx.pyz.sha256
install -m 755 ctx.pyz ~/.local/bin/ctx
export PATH="$HOME/.local/bin:$PATH"
ctx --version

可将 PATH 设置加入 ~/.bashrc。升级时重新下载、校验并安装；本地工作区和登录配置保留。ctx.pyz 是包含 Python 源码和 MIT 许可证的 ZIP，可直接查看源码。

导入 → 提交 → 推送

先在网站注册账号，再在终端登录。Windows 与 Linux 使用相同命令。密码交互输入，登录会话按站点保存在用户配置目录。

ctx auth login --username 你的用户名
ctx init --title "项目开发对话"
ctx add --codex  # 当前会话 + Git 工作区代码
# 也可以：ctx add ../claude-export.json --platform claude
ctx diff --staged
ctx commit -m "保存开发进度"
ctx push

add --codex 直接识别当前 Codex 会话并记住来源，无需手动导出文件，同时采集当前 Git 工作区的代码，包括未提交修改和未被忽略的未跟踪文件。普通终端仅自动选择与工作区目录完全匹配的唯一会话；多个候选时用 --thread ID 指定。在 Codex 内执行时，本轮会留到下次采集。首次 push 默认创建私有库，明确公开时才使用 --visibility public。文件导入遇到转换遗漏时，检查提示后再加 --confirm-import。

继续对话与同步

继续与 Codex 对话后，用 add . 同时更新已跟踪会话与代码。也可编辑受管 JSON；添加 Claude、DeepSeek 等外部文件仍使用 ctx add 文件名。

ctx status
ctx diff
ctx add .
ctx diff --staged
ctx commit -m "完成登录功能"
ctx push

# 另一台机器：登录后粘贴网站的分享链接
ctx clone 'https://contexthub.reflectstars.dev/?package=仓库ID' my-copy
cd my-copy
ctx pull

add . 刷新当前分支的已跟踪对话，采集代码后一起暂存；重复采集不生成空变更。人工修改会阻止覆盖，可用 --no-refresh 跳过对话刷新。--no-code 仅更新对话并保留旧代码；--code 路径可指定 Git 工作区。没有 Git 仓库时仅更新对话并提示。commit 只保存暂存区，push 不额外读取 Codex。本机来源绑定不进入上传包或 clone。pull 要求工作区干净；代码按文件三方比较，同文件不同修改会冲突，不自动拼接文本；对话保留字段级合并。支持 branch、switch、merge；clone 取得所选快照，网站保留远程版本历史。

代码与对话一起恢复

默认保存的代码包含工作区当前文件。上传、clone、Fork 和导出都会携带它们；在另一台机器无需原 Git 仓库即可恢复。

ctx add .
ctx diff --staged
ctx commit -m "保存代码与对话"
ctx push
ctx restore HEAD --to ../restored-project
ctx restore HEAD --snapshot SNAPSHOT_ID --to ../restored-snapshot
ctx restore HEAD --message MESSAGE_ID --to ../restored-message
# 同时创建 Codex 新会话：添加 --codex
# 多段对话或消息 ID 重名时另选 --conversation CONVERSATION_ID

目标必须是新目录，包含 code/ 源文件、conversations/ 中保留完整包的 ctx 工作区和 receipt.json。不会创建虚构的 .git 历史。--snapshot 与 --message 二选一；无代码关联的旧消息不会被推测补齐。--message 配合 --codex 时仅导入截至该消息的正文，完整包另行保留。

每次采集只关联对话最新一轮，表示保存时的代码，不代表消息生成时的执行状态。--resume 可核验已有恢复；Codex 原生导入状态不确定时不会自动重试。其版本、附件和工具状态限制仍适用。

含代码的包需逐个导入，默认保留包内代码；显式 --no-code 保留当前工作区旧代码，显式 --code 路径采集指定 Git 工作区。代码上限：128 个快照、每快照 10,000 文件、单文件 16 MiB、全部历史去重文件 64 MiB；整包解压合计 100 MiB。服务端可另设更小请求上限。

旧式 Git 提交检查点

只有 Git 提交关联、未携带代码的旧包，仍需本机拥有原代码提交。捕获要求代码与对话干净，恢复生成该提交的独立浅历史仓库。

ctx checkpoint --code ../my-project -m "固定 Git 提交"
ctx restore HEAD --code ../my-project --to ../restored-legacy

旧式流程不支持子模块、符号链接、LFS 指针或经过滤器/换行转换的工作文件；对话变化后要重新建立检查点。其代码仓库权限与 Hub 权限分别管理。

在网页按目录阅读

对话按日期与轮次组织，默认显示最新轮次；可搜索、切换前后轮，较长轮次分页。新采集使用真实 Codex 轮次开始时间，旧版本不自动补时间，缺失时显示“时间未记录”。

点击消息的“采集时的代码”查看对应快照；“代码”中按目录浏览文件、切换快照和查看真实 diff。“导入与处理记录”只说明格式转换、脱敏和人工编辑，没有代码关联的消息显示“未记录当时代码”。

复用别人的对话

公开库可匿名阅读，所有克隆、下载与写操作均须登录。修改别人的库时，先创建自己的 Fork。

ctx fork 'https://contexthub.reflectstars.dev/?package=仓库ID' my-fork
cd my-fork
# 修改、add、commit 后，可 push 到自己的副本
ctx remote
ctx log
ctx export ../shared.contextpack

Fork 默认私有，不改变原库。需要贡献回上游时，可创建公开 Fork，并在网站提交贡献请求。库拥有者可在网页设置中修改公开性，变更适用于全部历史版本。

分支、合并与普通 Git

ctx switch -c improve
# 编辑、add、commit 后
ctx switch main
ctx merge improve
ctx git export ../conversation-git
ctx git import ../conversation-git ../restored-context

Git 导出/导入目录必须不存在。导出的仓库可用普通 git clone、push 管理；导入读取其已提交的受管对话、包内代码与分支，不扫描任意项目文件。Hub 的 clone 下载所选快照，不提供原生 Git 协议服务。

连接本机 Codex

安装 Codex CLI 后，可以直接使用 ctx 的本地桥接命令。Windows 优先识别 codex.exe 和常见 npm 安装；找不到时，可将 CONTEXTHUB_CODEX_EXE 设为本机 codex.exe 完整路径。

ctx codex list
ctx codex export --thread 会话ID --title "项目讨论" -o codex.contextpack
ctx add codex.contextpack

# 下载并导出包后，在自己的机器检查，再导入
ctx codex import shared.contextpack --dry-run
ctx codex import shared.contextpack --cwd /absolute/path/to/project

默认在 Codex 0.153.4 中重建可继续的原生用户/助手文本时间线，并验证读回与 resume；其他版本可显式 --mode context 注入上下文。不调用模型，也不恢复原始回合时间、附件、工具状态或权限。Claude、DeepSeek 的原平台回导不在首版支持范围。

更多选项：ctx --help · 脚本输出：ctx --json status

自部署站点：登录和首次 push 使用 --hub https://你的Hub，或设置 CONTEXTHUB_HUB。
